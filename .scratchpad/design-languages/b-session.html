Risk checks

Seven checks run before any order reaches Alpaca.

Every order a strategy produces is checked in the same order: market hours, order size, the sleeve's own cash and holdings, allowed symbols, position size, the day's loss and the order rate. If a check fails, the order isn't sent and the session records which check stopped it.

If the ledger can't confirm the sleeve's state, the order is rejected. A missing answer never counts as a pass.

Limits shown are the defaults. Each session can set its own.

Session states

Every state has a name and a reason.

A strategy that isn't trading is usually doing the right thing. It may be waiting for a symbol's bar, outside its rebalance window, or stopped because the ledger and Alpaca disagree. Each of these has its own mark, so you can tell them apart at a glance.

The shape carries the meaning and the colour backs it up: a dashed ring for waiting, a half-filled ring for a degraded evaluation, a square for frozen.

Notes

The idea, and what building it would take

Clocks and gates

LlamaTrade's runtime is a set of clocks and gates: market hours, a bar stream that folds into a daily bar, a rebalance gate that opens on the schedule only when every symbol has data, reconciliation passes and a risk pipeline. Most confusion in a trading tool comes from not knowing which of these is holding things up.

This direction puts them on screen permanently. The status rail answers "is it working?" before any number is read, and every state has a shape as well as a colour. Times always carry a zone, numbers are always monospaced, and the only motion is a single flash when a price changes and a slow ring on things that are streaming.

It suits people who watch sessions during market hours. It's less suited to the marketing site and to occasional users, who meet a dense dark interface before they know what the parts mean.

Building it in the current app

  • Theme: new values in monolith.css under [data-theme="night"] and [data-theme="day"], re-enabling the retired toggle. Fonts swap to Chivo and Chivo Mono.
  • The status rail is a new component reading the market clock, the bar feed's last bar and the session's gate state. The gate and reconciliation timestamps would need to be exposed by the trading service to the web client if they aren't already.
  • State marks and the paper hatch are two small components that replace the current orange tags. Risk check results already return the failing checks, so the stopped-order view is a rendering of existing data.
  • Price flashes need the market-data stream on the session page; the current trading page is a read-only blotter, so this is new wiring, not restyling.
  • Most other screens are restyling: hard shadows, uppercase labels and orange accents come out, and table rows move to the 32 px rhythm.
